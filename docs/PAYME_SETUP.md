# Payme Merchant API — интеграция

Автоматическое пополнение баланса бота через Payme (только UZS).

Оплата подтверждается **Merchant API**, а не редиректом браузера. Источник
правды — состояние транзакции в Payme, которое приходит на наш webhook.

---

## Как это работает

```
Клиент в боте: «Пополнить» → выбирает Payme
        │
        ▼
Бот создаёт TopUp (method=payme, status=pending) и строит checkout-ссылку
        │  account[topup_id] = <id>,  a = <сумма в тийинах>
        ▼
Клиент открывает Payme checkout (кнопка) и платит
        │
        ▼
Серверы Payme вызывают наш webhook  POST /api/payme  (JSON-RPC 2.0)
        │
        ├─ CheckPerformTransaction  — можно ли платить (сумма, статус)
        ├─ CreateTransaction        — создаётся транзакция (state 1)
        ├─ PerformTransaction       — ОПЛАЧЕНО: state 2 + баланс зачислен
        ├─ CancelTransaction        — отмена / возврат (state -1 / -2)
        └─ CheckTransaction         — текущее состояние
        │
        ▼
Webhook (Next.js) атомарно: TopUp=approved + BotUser.balance += сумма
        │
        ▼
Бот (отдельный процесс) видит approved-пополнение → уведомляет клиента
        и, если было «купить товар», выдаёт товар автоматически
```

Два процесса, одна база: **webhook живёт в Next.js**, **выдача — в боте**.
Деньги зачисляет только webhook; бот только уведомляет и выдаёт.

## Переменные окружения

Заполнять в **Railway → Variables** (не в файле репозитория).

| Переменная | Значение |
|---|---|
| `PAYME_ENABLED` | `1` — включить. Пока `0`/пусто: кнопка Payme скрыта, webhook отклоняет всё |
| `PAYME_MERCHANT_ID` | ID кассы из кабинета мерчанта Payme |
| `PAYME_KEY` | Ключ мерчанта для авторизации webhook. Тестовый и боевой — разные |
| `PAYME_CHECKOUT_URL` | `https://checkout.paycom.uz` (бой) или `https://checkout.test.paycom.uz` (песочница) |
| `APP_URL` | Публичный адрес Next.js — на нём Payme дергает `/api/payme` |

`PAYME_KEY` — секрет. Не коммитить, не логировать (webhook его не пишет в лог).

## Изменения в БД

- Новая таблица **`PaymeTransaction`** — одна строка на транзакцию Payme:
  `paymeId` (уникален), `topUpId` (уникален), `amountTiyin`, `state`,
  `createTime/performTime/cancelTime`, `reason`.
- В **`TopUp`** добавлено поле `deliveredAt` — метка «бот уже уведомил/выдал».

Таблица и колонка создаются автоматически при старте бота (`ensureSchema`),
поэтому отдельная миграция на деплое не требуется. Схема Prisma обновлена —
`npm run db:push` применит её и напрямую.

## Merchant API endpoint

`POST /api/payme` — JSON-RPC 2.0. Всегда отвечает **HTTP 200** (ошибки —
в теле). Авторизация: HTTP Basic, логин `Paycom`, пароль = `PAYME_KEY`.
Неверный ключ или `PAYME_ENABLED != 1` → ошибка `-32504`.

В кабинете Payme укажите endpoint: `https://<APP_URL>/api/payme`.

### Состояния транзакции

| state | Значение |
|---|---|
| `1` | Создана, ждёт оплаты |
| `2` | Оплачена (баланс зачислен) |
| `-1` | Отменена до оплаты |
| `-2` | Отменена/возврат после оплаты |

```
        CreateTransaction          PerformTransaction
  (нет)  ───────────────►  1  ──────────────────────►  2
                            │                            │
             CancelTransaction              CancelTransaction (возврат)
                            ▼                            ▼
                           -1                           -2
```

### Коды ошибок

| Код | Значение |
|---|---|
| `-32504` | Нет доступа (неверный ключ / выключено) |
| `-31001` | Неверная сумма |
| `-31003` | Транзакция не найдена |
| `-31007` | Заказ выполнен, отмена невозможна (баланс уже потрачен) |
| `-31008` | Невозможно выполнить операцию |
| `-31050` | Пополнение не найдено (`data: "topup_id"`) |
| `-31051` | Пополнение уже оплачено/отменено |

### Пример: PerformTransaction

Запрос от Payme:
```json
{ "jsonrpc": "2.0", "id": 1, "method": "PerformTransaction",
  "params": { "id": "5305e3bab097f420a62ced0b" } }
```
Ответ:
```json
{ "jsonrpc": "2.0", "id": 1,
  "result": { "transaction": "5305e3bab097f420a62ced0b",
              "perform_time": 1700000000000, "state": 2 } }
```

## Checkout-ссылка

Строится в боте (`buildCheckoutUrl`): base64 строки
`m=<MERCHANT_ID>;ac.topup_id=<id>;a=<тийины>` после `PAYME_CHECKOUT_URL/`.
Сумма — в **тийинах** (сум × 100). 50 000 сум = 5 000 000 тийин.

---

## Идемпотентность и деньги

- `PaymeTransaction.paymeId` уникален — повтор `CreateTransaction`/
  `PerformTransaction` не создаёт вторую строку.
- `PerformTransaction` зачисляет баланс в одной транзакции БД с блокировкой
  строки (`SELECT … FOR UPDATE`) и переходом строго `1 → 2`. Два одновременных
  вызова или ретрай Payme → **зачисление ровно один раз**.
- Суммы сверяются целыми тийинами (`round(сум × 100)`), без float.
- Редирект/callback **не** подтверждает оплату — только webhook.

---

## Как клиент узнаёт статус

Клиент — в боте. После оплаты webhook зачисляет баланс, а бот в течение
~12 секунд присылает «Оплата получена, баланс пополнен» и, если пополнение
было ради покупки, сразу выдаёт товар.

## Локальный тест

Payme должен достучаться до `/api/payme`, поэтому нужен публичный адрес.

1. `npm run dev` (Next.js) и `npm run bot` (бот) — два процесса.
2. Прокиньте локальный порт наружу (напр. туннель) и укажите этот адрес как
   endpoint в кабинете песочницы Payme; `PAYME_CHECKOUT_URL=https://checkout.test.paycom.uz`.
3. Прогоните сценарии песочницы Payme (CheckPerform/Create/Perform/Cancel/Check).
4. Протокольная логика покрыта юнит-тестами без сети:
   ```bash
   npx vitest run tests/payme.test.ts
   ```

Перед боем проверьте с маленькой суммой, что баланс зачисляется и товар
выдаётся.

## Что нужно от Payme

- Договор мерчанта и доступ в кабинет Payme Business.
- ID кассы (`PAYME_MERCHANT_ID`).
- Тестовый и боевой ключ (`PAYME_KEY`).
- Прописать endpoint `https://<APP_URL>/api/payme` в кабинете.

## Прод-конфигурация

- `PAYME_CHECKOUT_URL=https://checkout.paycom.uz` + боевой `PAYME_KEY`.
- `APP_URL` — реальный HTTPS-домен Next.js.
- `PAYME_ENABLED=1` в последнюю очередь, после проверки в песочнице.

## Открытые вопросы (подтвердить по песочнице Payme)

Реализация следует общепринятому Payme-протоколу. Против официального
sandbox-набора стоит подтвердить:

- Точные под-коды account-ошибок (`-31050/-31051`) — Payme проверяет диапазон
  `-31050..-31099` и поле `data`.
- Поведение таймаута транзакции (сейчас 12 часов → `-31008`).
- Правила отмены после оплаты для возврата на баланс (сейчас: возврат если
  средства не потрачены, иначе `-31007`).
